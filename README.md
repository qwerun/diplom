# Система управления рекламными кампаниями университета

Учебный прототип веб-приложения для управления рекламными кампаниями, активностями, каналами продвижения, метриками, отчетами и аналитикой.

Проект сделан намеренно простым: backend хранится в одном Django-приложении `core`, роли реализованы через профиль стандартного пользователя Django, база по умолчанию SQLite. Такой вариант легче защитить и доработать в рамках студенческой работы.

## Стек

Backend:
- Python
- Django
- Django REST Framework
- Simple JWT
- django-filter
- drf-spectacular
- openpyxl
- SQLite для локального запуска, PostgreSQL можно подключить позже

Frontend:
- React
- Vite
- React Router
- Axios
- Recharts
- обычный CSS

## Запуск backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python manage.py makemigrations
python manage.py migrate
python manage.py seed
python manage.py runserver
```

После `seed` будут созданы тестовые пользователи:

| Логин | Пароль | Роль |
| --- | --- | --- |
| admin | 12345678 | Администратор |
| manager | 12345678 | Менеджер |
| executor | 12345678 | Исполнитель |
| head | 12345678 | Руководитель |

API:
- `POST /api/auth/login/`
- `POST /api/auth/refresh/`
- `GET /api/auth/me/`
- `GET /api/campaigns/`
- `GET /api/activities/`
- `GET /api/activity-results/`
- `GET /api/metric-values/`
- `POST /api/reports/generate/`
- `GET /api/reports/{id}/xlsx/`
- `GET /api/analytics/dashboard/`
- `GET /api/docs/`

## Запуск frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend по умолчанию ожидает backend на `http://127.0.0.1:8000/api`.

Если адрес другой, создайте файл `frontend/.env`:

```text
VITE_API_URL=http://127.0.0.1:8000/api
```

## Что реализовано

- вход по JWT;
- получение текущего пользователя;
- CRUD API для пользователей, статусов, кампаний, каналов, источников метрик, активностей, результатов, типов метрик, значений метрик и отчетов;
- XLSX-отчет по кампании;
- аналитика по статусам, метрикам и каналам;
- React-страницы для основных разделов;
- вложенный экран кампании: кампания содержит активности, активность содержит результат и метрики;
- управляемые переходы статусов через справочник и матрицу переходов;
- стартовые статусы кампаний и активностей назначаются на backend;
- базовая валидация дат, бюджета и значений метрик;
- серверные проверки прав и жизненного цикла дублируют важные ограничения интерфейса;
- реальный API-сбор метрик для VK через `wall.getById`;
- реальный API-сбор метрик для Telegram через MTProto/Telethon;
- seed-данные для первого запуска.

## Настройка API-сбора метрик

Для VK в `.env` нужно указать:

```text
VK_ACCESS_TOKEN=...
VK_API_VERSION=5.199
```

Ссылка результата должна быть похожа на:

```text
https://vk.com/wall-123456_789
```

Собираются метрики: просмотры, лайки, комментарии, репосты.

Для Telegram просмотры поста нельзя получить через Bot API. Используется MTProto через Telethon, поэтому нужны данные приложения Telegram и строка пользовательской сессии:

```text
TELEGRAM_API_ID=...
TELEGRAM_API_HASH=...
TELEGRAM_SESSION_STRING=...
```

Ссылка результата должна быть похожа на:

```text
https://t.me/channel_name/123
```

Собираются метрики: просмотры, реакции как лайки, комментарии/ответы, репосты/пересылки.

## Упрощения

- для локальной разработки используется SQLite;
- роли не вынесены в отдельную таблицу, а заданы в профиле пользователя;
- отчет формируется как Excel-файл `.xlsx`;
- активности, результаты и метрики ведутся внутри карточек кампаний/активностей, чтобы не дублировать отдельные разделы;
- права доступа сделаны простыми: администратор управляет пользователями и статусами, менеджер редактирует основные сущности, исполнитель может работать с результатами активностей, руководитель в основном просматривает данные.
- в коде временно добавлены поясняющие комментарии для проверки и защиты работы; перед финальной сдачей их можно будет удалить.
